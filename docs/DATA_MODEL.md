# Data Model Direction

## Shared platform core
People, Organizations, Organization Memberships, Roles, Permissions, Simulation Types, Organization Simulation Access, Sessions, Teams/Assignments, Consent Templates/Consents, Evaluations/Observations, Communications, Files, Audit Events.

## Simulation engine
Scenario, Scenario Version, Rounds/Phases, Metrics, Decisions, Events, Disruptions, Triggers, Consequences/Effects and persisted Session State.

## Belonging module
Community Partners, Partner Needs, Collection Categories, Collection Transactions, Outreach Activity and Partner Handoffs.

## CityLab module
Jurisdictions, Map Areas/Parcels, Population/Demographics, Stakeholders, Infrastructure Assets, Natural/Environmental Assets, Land Use/Zoning, Economic Assets/Employers, Municipal Finances, Projects/Initiatives, Project Effects and Territory History.

Western Kentucky is scenario content, not application logic.

## Versioning
CityLab hierarchy: `CityLab → Scenario → Scenario Version → Session`.
A session references a fixed scenario version. Published versions are not edited in place.

## Development data
Test sessions use `mode=development` and `is_development=true`. Operational rows generated by those sessions must inherit that state. Production reporting excludes development data by default.
